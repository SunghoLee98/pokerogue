# 협동 모드 4단계: 전투 Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking. 각 Task는 실패하는 테스트 → 실패 확인 → 구현 → 통과 확인 → 커밋 순서로 진행한다.

**Goal:** 협동 런의 모든 전투를 2대2(원래 적 1마리 고정인 전투는 2대1)로 치르고, 두 클라이언트가 각자 자기 필드 포켓몬의 명령만 입력한 뒤 상대 명령을 받아 같은 턴을 실행한다(락스텝). 볼·공격·교체·테라스탈은 독립적이고, 도망은 둘의 동의가 있어야 하며, 잡은 포켓몬은 던진 사람 소유가 된다. 한쪽이 전멸하면 파트너 혼자 싸우는 지원 모드가 된다. 기록-재생 테스트로 호스트 실행과 게스트 실행의 해시 순서가 같음을 보인다.

**Architecture:** 로직은 모두 `src/coop/`에 두고 코어는 얇은 훅만 단다.
- 전투 규칙(`coop-battle-rules.ts`): 더블 강제, 단일 고정 전투의 적 수, 최종보스 1단계 능력치 배율, 웨이브 시작 교체 질문 생략.
- 입력 중개자(`coop-input-broker.ts`, 스펙 4.3 `CoopInputBroker`): 전송 객체 위에서 상대 입력을 키(웨이브·턴 또는 결정 순번)별로 받아 두고, 기다리는 쪽에 순서대로 넘긴다. 세션마다 하나.
- 턴 명령(`coop-turn-commands.ts`): `CommandPhase`의 협동 분기. 필드 자리의 포켓몬 **주인**이 로컬이면 기존 UI, 아니면 대기 문구를 띄우고 상대의 `turnCommand`를 기다려 그대로 넣는다. 로컬 자리 명령을 먼저 받도록 상대 자리 `CommandPhase`를 뒤로 미룬다(두 사람이 동시에 입력). 도망 제안·동의·거절 규칙도 여기 있다.
- 볼(`coop-ball.ts`): 적이 둘이면 볼 대상 선택, 같은 대상 이중 포획 규칙, 던진 사람 정보.
- 포획(`coop-capture.ts`): 던진 사람 소유 등록, 소유자별 3마리 한도, 바꾸기/놓아주기 결정을 던진 사람이 내리고 상대는 기다림.
- 필드와 교체(`coop-field.ts`): 웨이브 시작 시 필드 자리 배치(0번 호스트, 1번 게스트, 전멸한 쪽은 빈자리), 교체 후보를 자기 포켓몬으로 제한, 교체 결정 전달.

**Tech Stack:** TypeScript, vitest(jsdom), 기존 `GameManager` 테스트 프레임워크, `LoopbackTransport`, 기록-재생 도구(`test/utils/coop-replay.ts`)

**Spec:** `docs/superpowers/specs/2026-10-12-coop-mode-design.md` 3.3(전투), 3.4(쓰러짐과 지원 모드), 3.9(단일 고정 전투), 4.3(`CoopInputBroker`), 4.4 전투 행(더블 강제, 단일 고정 전투 적 수, 최종보스 능력치, ME 더블, 스토리 전투, 볼 사용 제한, 도망 동의, 명령 입력, 포획, 파티 크기, 교체), 5장 필수 시나리오 중 전투 항목

**앞 계획:** `2026-10-12-coop-03-connect-and-starters.md` 구현 메모 12번(명령 분배), `2026-10-12-coop-02-determinism.md`(크리티컬 포획 도감 수, 기록-재생 도구), 스펙 4.4 필드 위치 규칙

**단계 나누기:** 범위가 커서 둘로 나눈다. 같은 브랜치에서 순서대로 구현한다.
- **4a (Task 1~5)**: 2대2 강제, 단일 고정 전투, 최종보스 1.5배, 입력 중개자, 명령 분배, 기록-재생 도구 확장
- **4b (Task 6~10)**: 볼과 포획 소유권, 도망 동의, 교체·쓰러짐·지원 모드, 시나리오 재생, 화면 확인

## Global Constraints

- **솔로 동작은 그대로다.** 모든 훅은 `coopSession`이 `null`이면 기존 코드와 같은 값을 내고 같은 함수를 부른다.
- 코어(`src/` 중 `src/coop/` 바깥) 변경은 훅 호출과 import, 훅에 필요한 최소한의 인자 추가(예: `AttemptCapturePhase`의 던진 포켓몬 id)로 제한한다. 주변 코드는 리팩터링하지 않는다.
- **전투 시뮬레이션에는 최종 명령만 들어간다.** 대기, 도망 제안·거절, 볼 대상 고르기는 모두 `TurnStartPhase` 전에 끝난다. 시뮬레이션 중 사람이 고르는 지점(교체, 포획 후 바꾸기)은 주인이 고른 결과를 결정 순번 키로 보내고 양쪽이 같은 함수로 적용한다.
- 받은 상대 명령은 다시 검증하지 않는다(신뢰 기반, 스펙 2장). 로컬 검증은 로컬 계정으로 한다(예: `checkCanUseBall`의 도감 검사).
- 명령을 낼 사람은 **필드 자리의 포켓몬 주인**으로 정한다(자리 번호가 아님). 자리 배치가 잠시 어긋나도 남의 포켓몬을 조작하지 않는다.
- 테스트당 `GameManager` 하나 제약(2단계 구현 메모 2번)과 "타이틀을 지난 뒤 세션을 연다"(3단계 구현 메모 3번)를 지킨다.
- 새 파일은 kebab-case, biome 통과(경고 포함), 번역 문구는 `coopText`(3단계 구현 메모 9번).

## Review Focus

1. **양쪽 해시가 같은가**: 둘 다 볼, 볼+공격, 같은 대상 이중 포획, 도망 제안 동의/거절, 한쪽 전멸 후 지원 모드, 최종보스 2대1에서 호스트 실행과 게스트 실행의 해시 순서가 같다. → Task 5, 10 재생 테스트.
2. **내 자리만 조작하는가**: 게스트 클라이언트에서 필드 0번 명령 UI가 뜨지 않고 대기 문구가 뜬다. 상대 명령이 오기 전에는 턴이 실행되지 않는다. → Task 4.
3. **볼이 파트너 명령을 지우지 않는가**: 솔로의 "볼/도망이면 다른 자리 명령 skip"이 협동에서 꺼진다. → Task 6.
4. **최종보스 배율**: 협동 1단계만 1.5배, 2단계와 솔로는 배율 없음. 훅을 지우면 테스트가 실패한다(변이 확인). → Task 3, 10.
5. **빈자리를 남의 포켓몬으로 채우지 않는가**: 한쪽 전멸 시 그 자리는 비고, 다음 웨이브에도 비며, 부활하면 다음 웨이브에 돌아온다. → Task 9.

### B. 명령 흐름 (락스텝)

턴마다 두 클라이언트 모두 `TurnInitPhase`가 `CommandPhase(0)`, `CommandPhase(1)`을 넣는다.

1. 상대 자리 `CommandPhase`가 먼저 시작되고 뒤에 로컬 자리 `CommandPhase`가 있으면, 로컬 자리 → 상대 자리 순서로 다시 넣는다(게스트에서 자리 1을 먼저 입력). 두 클라이언트 모두 "로컬 입력 → 상대 대기" 순서가 되어 동시에 입력한다. `CommandPhase`는 공유 RNG를 쓰지 않으므로 순서가 달라도 결과가 같다.
2. 커맨더·skip·예약된 기술(연속기, 충전 2턴째)은 양쪽이 같은 시뮬레이션 상태로 같은 자동 명령을 만든다. 보내지 않는다.
3. 입력이 필요한 로컬 자리는 기존 UI(명령 → 기술 → 대상)로 고른다. 확정된 명령은 다음 상대 자리 대기 시작 때나 `TurnStartPhase` 시작 때 `turnCommand { wave, turn, command: { fieldIndex, turnCommand, preTurnCommand } }`로 보낸다(대상 선택이 끝난 뒤라야 최종이다).
4. 상대 자리 대기는 "파트너의 입력을 기다리는 중..."을 띄우고, 그 턴의 수신함을 도착 순서대로 읽는다.
5. 두 명령이 모이면 도망 규칙을 적용한다: 둘 다 입력이 필요했던 턴에 한쪽만 RUN이면 그 RUN은 무효다(로컬이면 다시 고름, 상대 것이면 버리고 다음 명령을 기다림). 둘 다 RUN이면 자리 1 명령을 `skip`(도망 시도 1회). 지원 모드나 상대 자리가 자동 명령이면 혼자 RUN이 유효하다.

도망 제안 UI(스펙 3.3): 상대의 RUN이 도착했을 때 로컬 자리 입력 중이면 "파트너가 도망치려 합니다. 같이 도망칠까요?" 확인 창을 띄운다. 동의 = 로컬 RUN 확정. 거절 = 받은 RUN을 버리고 `confirm { kind: "flee", accepted: false }`를 보낸 뒤 명령 화면으로 돌아간다. 제안한 쪽은 거절을 받거나, 상대의 RUN 아닌 명령을 받으면 명령 선택 화면으로 돌아간다(턴을 잃지 않음).

### C. 결정 순번

교체(`SwitchPhase`)와 포획 후 바꾸기/놓아주기는 턴 실행 중에 사람이 고른다. 양쪽 시뮬레이션은 같은 순서로 이 지점에 닿으므로 세션의 결정 순번(0부터 1씩)을 키로 `choice { kind: "switch" | "capture", wave, payload: { seq, ... } }`를 주고받는다.

### D. 3단계 인계 사항 처리

| 인계 | 처리 |
|---|---|
| 한 클라이언트가 두 자리를 조작 | B의 명령 흐름 |
| `checkCanUseBall`이 로컬 `gameData` | 로컬 자리 입력에서만 부른다. 받은 명령은 검증하지 않는다 |
| 크리티컬 포획 도감 수 | 던진 포켓몬 주인 스냅샷(A표) |
| 파티 순서 불변식 | 웨이브 시작 배치(A표 마지막 줄). 전투 중 자리 변화는 교체(같은 주인끼리)로만 일어난다 |
